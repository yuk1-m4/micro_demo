# 0005. 金額計算のテストの厳しさを Avito 版 go-mutesting で検査する

- 日付: 2026-11-24
- 状態: 採用
- 関連: Linear WORK-14（WORK-13・WORK-12）

## 背景
AI エージェントはテストを通すことを目指して動くので、テストに穴があると誤ったコードも CI を通る。
金額計算は1か所の端数の誤りが全取引に及ぶが、カバレッジでは `>=` と `>` の違いなどを検出できない。
Go のミューテーションテストには定番と言えるツールがない。gremlins は利用者が最も多いが、更新が鈍く、演算子しか壊さない。

## 決定
金額計算のパッケージに限り、avito-tech/go-mutesting によるミューテーションテストを CI の関門にする。
決め手は、企業が保守を続けていることと、文の削除の変異で `decimal.Round()` などライブラリの呼び出しも検査できること。
gremlins（演算子のみ・0.x 系）、本家 zimmski 版（2021年に停止）、個人開発のフォーク（利用者がほぼいない）は不採用。
期待値は人が確かめた値か `big.Rat` の別実装から取り、エージェントには決めさせない。

## 結果
- テスト自体の穴（丸めの境目、返金の符号など）を機械的に落とせる。
- ミュータントと等価ミュータントが増え、仕分けの手間と実行時間が gremlins より大きい。対象を絞ることで抑える。
- 保守は1社に依存している。バージョンを固定し、設定はツールに強く依存させない。
